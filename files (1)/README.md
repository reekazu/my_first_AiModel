# Автосверка актов сверки

Прототип: сравнивает выгрузку взаиморасчётов из 1С с актом сверки,
присланным контрагентом, и показывает только реальные расхождения —
вместо ручного построчного сравнения в Excel.

## Как это работает

1. Оба файла (наш и контрагента) приводятся к единому виду: дата,
   номер документа, сумма.
2. Сначала операции сопоставляются по номеру документа (устойчиво
   к разнице в формате: "№0000123" и "123" — это одно и то же).
3. То, что не нашло пару, пытаемся сопоставить по дате (с допуском
   в днях) и сумме (с допуском в рублях) — контрагенты часто
   присылают акт с задержкой в проведении документа на пару дней.
4. Всё, что так и не нашло пару, или нашлось, но с разной суммой —
   выводится отдельно как расхождение. Это и есть то, что нужно
   бухгалтеру разбирать руками.

## Запуск

```bash
cd recon_app
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Откроется браузер на `http://localhost:8501`. Там:

1. Загрузите Excel-выгрузку из 1С.
2. Загрузите Excel-акт от контрагента.
3. Для каждого файла укажите, какая колонка — дата, какая — сумма
   (или отдельно дебет/кредит), какая — номер документа.
4. Нажмите «Сверить» и скачайте готовый Excel-отчёт с вкладками
   по видам расхождений.

## Проверка на тестовых данных

В `sample_data/` уже лежат два готовых файла с намеренными
расхождениями (`our_1c_export.xlsx` и `counterparty_act.xlsx`) —
их можно сразу загрузить в приложение, чтобы увидеть, как это
работает, ещё до подключения реальных данных. Пересоздать их:

```bash
python3 sample_data/make_samples.py
```

## Что стоит доработать в первую очередь

1. **Прямая выгрузка из 1С.** Сейчас на входе — Excel-файл, экспортированный
   вручную. Следующий шаг — забирать данные напрямую через
   1С:Предприятие (COM/OLE на Windows, или через HTTP-сервис/OData,
   если он настроен в конфигурации) — это уберёт ручной шаг экспорта.
2. **Разбор PDF-актов.** Многие контрагенты присылают акт не в Excel,
   а как PDF или скан. Стоит добавить извлечение таблиц из PDF
   (`pdfplumber`/`camelot`) или хотя бы OCR для сканов — сейчас это
   не поддержано и файл нужно сначала превратить в Excel вручную.
3. **Память о сопоставлении колонок.** Если один и тот же контрагент
   присылает акты в одном формате каждый месяц, сопоставление колонок
   стоит запоминать (например, в JSON-конфиге по имени контрагента),
   чтобы не настраивать заново каждый раз.
4. **Более умное сопоставление.** Сейчас логика — точный номер, потом
   дата+сумма. Для сложных случаев (частичные оплаты, объединённые
   платёжки на несколько накладных) стоит добавить сопоставление
   "один ко многим" — когда одна операция у нас соответствует
   нескольким у контрагента (и наоборот), с проверкой, что суммы
   в сумме сходятся.
5. **История и напоминания.** Сохранять результаты сверки по
   контрагентам в базу (SQLite для начала) и показывать, у кого
   расхождения повторяются из месяца в месяц — это обычно и есть
   самое полезное для бухгалтерии.
