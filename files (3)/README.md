# Автосверка актов сверки

Прототип: сравнивает выгрузку взаиморасчётов из 1С с актом сверки,
присланным контрагентом, и показывает только реальные расхождения —
вместо ручного построчного сравнения в Excel.

## Как это работает

1. Оба файла (наш и контрагента) приводятся к единому виду: дата,
   номер документа, сумма.
2. Сначала операции сопоставляются по номеру документа (устойчиво
   к разнице в формате: "№0000123" и "123" — это одно и то же).
3. То, что не нашло пару, пытаемся сопоставить по дате (с допуском
   в днях) и сумме (с допуском в рублях) — контрагенты часто
   присылают акт с задержкой в проведении документа на пару дней.
4. Всё, что так и не нашло пару, или нашлось, но с разной суммой —
   выводится отдельно как расхождение. Это и есть то, что нужно
   бухгалтеру разбирать руками.

## Работа с PDF (в т.ч. сканами)

Теперь можно загружать не только Excel, но и PDF — и для нашей выгрузки,
и для акта контрагента. Внутри три разных сценария, приложение определяет
нужный автоматически:

1. **PDF с настоящей таблицей** (с линиями/границами ячеек) — таблица
   вытаскивается напрямую, распознавание не требуется, результат точный.
2. **PDF с текстовым слоем, но без таблицы** (просто текст, сформированный
   из 1С/Word "в PDF") — строки разбираются эвристически: ищем в каждой
   строке дату, номер документа (по «№») и суммы.
3. **Скан / фотография акта** (текстового слоя нет вообще) — сначала OCR
   (Tesseract) распознаёт текст по картинке страницы, дальше — тот же
   эвристический построчный разбор, что и в пункте 2.

Для сценариев 2 и 3 результат — **черновик**, который показывается в
редактируемой таблице прямо в приложении: OCR и эвристика ошибаются
(путают "0"/"О", съезжают разделители разрядов), поэтому строки нужно
проверить и при необходимости поправить до того, как нажимать «Сверить».

**Важное ограничение построчного разбора:** он ищет в строке "первое
число" и "второе число", а не значения строго из колонок «Дебет»/
«Кредит» — если в строке заполнена только одна из колонок, число всё
равно попадёт в `amount_1`. Это значит, что для сканов лучше сразу
проверять знак каждой суммы в редактируемой таблице, а не полагаться
на автоматическое разнесение по дебету/кредиту.

Для распознавания кириллицы понадобится русский языковой пакет
Tesseract — без него текст на сканах будет распознаваться как англ.
"тарабарщина". Команда для установки — в комментариях `requirements.txt`.

### Windows: если pdftoppm/tesseract "не найдены"

На Windows Poppler и Tesseract часто ставятся, но не попадают в PATH
автоматически — тогда Python их не находит, хотя они физически на диске
есть. Ошибка будет понятной (не трейсбек), с инструкцией, но короче: если
не хочется трогать системный PATH, впишите полные пути в начало файла
`pdf_import.py`:

```python
POPPLER_BIN_DIR = r"C:\poppler-24.08.0\Library\bin"
TESSERACT_EXE = r"C:\Program Files\Tesseract-OCR\tesseract.exe"
```

Poppler для Windows: https://github.com/oschwartz10612/poppler-windows/releases
(нужна папка `Library\bin` из архива).
Tesseract для Windows: сборка UB-Mannheim
https://github.com/UB-Mannheim/tesseract/wiki — при установке обязательно
отметьте галочку **Russian** в списке языков, иначе распознавание
кириллицы не заработает даже при найденной программе.

## Запуск

```bash
cd recon_app
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

Откроется браузер на `http://localhost:8501`. Там:

1. Загрузите Excel-выгрузку из 1С.
2. Загрузите Excel-акт от контрагента.
3. Для каждого файла укажите, какая колонка — дата, какая — сумма
   (или отдельно дебет/кредит), какая — номер документа.
4. Нажмите «Сверить» и скачайте готовый Excel-отчёт с вкладками
   по видам расхождений.

## Что стоит доработать в первую очередь

1. **Прямая выгрузка из 1С.** Сейчас на входе — Excel-файл, экспортированный
   вручную. Следующий шаг — забирать данные напрямую через
   1С:Предприятие (COM/OLE на Windows, или через HTTP-сервис/OData,
   если он настроен в конфигурации) — это уберёт ручной шаг экспорта.
2. **Более надёжный разбор сканов.** Базовый OCR уже есть, но эвристика
   "первое число / второе число в строке" ошибается, когда в исходной
   таблице заполнена только одна из колонок Дебет/Кредит. Следующий шаг —
   использовать координаты слов из `pytesseract.image_to_data` (а не
   просто текст), чтобы восстанавливать колонки по их горизонтальной
   позиции на странице, а не по порядку чисел в строке.
3. **Память о сопоставлении колонок.** Если один и тот же контрагент
   присылает акты в одном формате каждый месяц, сопоставление колонок
   стоит запоминать (например, в JSON-конфиге по имени контрагента),
   чтобы не настраивать заново каждый раз.
4. **Более умное сопоставление.** Сейчас логика — точный номер, потом
   дата+сумма. Для сложных случаев (частичные оплаты, объединённые
   платёжки на несколько накладных) стоит добавить сопоставление
   "один ко многим" — когда одна операция у нас соответствует
   нескольким у контрагента (и наоборот), с проверкой, что суммы
   в сумме сходятся.
5. **История и напоминания.** Сохранять результаты сверки по
   контрагентам в базу (SQLite для начала) и показывать, у кого
   расхождения повторяются из месяца в месяц — это обычно и есть
   самое полезное для бухгалтерии.
