# Сверка актов сверки (1С vs контрагент)

Прототип программы, которая автоматически сравнивает вашу выгрузку из 1С
с актом/выгрузкой, полученной от контрагента, и находит расхождения:
не хватает операций с одной из сторон, разошлись суммы или номера
документов.

## Стек
- **Python 3** + **pandas** / **openpyxl** — чтение Excel-выгрузок и запись отчёта
- **Streamlit** (опционально) — веб-интерфейс без командной строки

Ничего кроме этого не требуется: не нужен доступ к самой 1С, работаем
с уже выгруженными Excel-файлами (стандартный способ обмена актами
сверки с контрагентами).

## Файлы
```
reconcile_core.py     ядро: чтение файлов, распознавание колонок, сопоставление
report_builder.py      сборка итогового Excel с подсветкой расхождений
reconcile_cli.py        запуск из командной строки
app.py                  веб-интерфейс (Streamlit)
make_sample_data.py     генератор тестовых файлов с заведомыми расхождениями
```

## Установка
```bash
pip install pandas openpyxl streamlit
```

## Быстрая проверка на тестовых данных
```bash
python make_sample_data.py
python reconcile_cli.py sample_our.xlsx sample_contractor.xlsx -o результат.xlsx
```
Откройте `результат.xlsx` — там 6 листов: Сводка и по одному листу
на каждый тип совпадения/расхождения, с цветовой подсветкой.

## Использование с реальными файлами
```bash
python reconcile_cli.py "выгрузка_1С.xlsx" "акт_от_контрагента.xlsx" -o результат.xlsx
```

Если суммы у сторон отражены зеркально (там, где у нас дебет — у
контрагента по этой же операции кредит, что нормально для акта
"куплю-продажа" с двух точек зрения), добавьте флаг:
```bash
python reconcile_cli.py our.xlsx their.xlsx -o результат.xlsx --mirror
```

Если в файле несколько листов или таблица не на первом:
```bash
python reconcile_cli.py our.xlsx their.xlsx --our-sheet "Акт сверки" --their-sheet 1
```

## Веб-интерфейс (для бухгалтера, без терминала)
```bash
streamlit run app.py
```
Откроется страница в браузере: загружаете два файла, жмёте «Сверить»,
скачиваете готовый отчёт.

## Как это работает
1. Программа сама ищет строку заголовков таблицы в первых 20 строках
   файла (1С обычно добавляет сверху название организации, период и
   т.п.) — ищутся слова «Дата», «Документ», «Дебет», «Кредит».
2. Каждая операция сопоставляется между сторонами в три прохода:
   - точное совпадение по номеру документа + дате + сумме;
   - совпадение по дате и сумме (если номер документа оформлен
     по-разному — например, «Акт №4» и «Акт 4»);
   - совпадение по номеру документа с разошедшейся суммой/датой —
     попадает в лист расхождений с указанием обеих сумм.
3. Всё, что не нашло пару — попадает в «Только у нас» / «Только у
   контрагента».

## Что стоит доработать в первую очередь
1. **Подключение напрямую к 1С.** Сейчас нужен ручной экспорт в Excel.
   На Windows с установленной 1С это можно автоматизировать через
   `pywin32` (COM-подключение к 1С:Предприятие) или через
   HTTP-сервис/OData, если он настроен в базе — тогда сверка будет
   запускаться одной кнопкой без выгрузки файлов вручную.
2. **Более гибкое распознавание форматов.** Разные конфигурации 1С
   (Бухгалтерия, Управление торговлей, ERP) экспортируют акты
   по-разному. Стоит собрать несколько реальных примеров от вашей
   бухгалтерии и контрагентов и расширить `COLUMN_KEYWORDS` и парсинг
   дат/сумм под них.
3. **Настройка допуска (толеранса).** Сейчас расхождение до 1 копейки
   игнорируется — вынести порог в параметр (например, игнорировать
   расхождения до 1 рубля из-за округлений).
4. **История сверок и статусы.** Сохранять результаты по каждому
   контрагенту в базу (SQLite/Postgres), чтобы видеть динамику и не
   пересверять то, что уже подтверждено.
5. **Пакетный режим.** Сверка сразу по папке с несколькими
   контрагентами + сводный отчёт по всем, для ежемесячного закрытия.
6. **Уведомления.** Автоматическая отправка письма контрагенту со
   списком расхождений сразу после сверки (через `smtplib` или
   API почтового сервиса).
7. **Более точная бухгалтерская логика.** Текущее сопоставление
   сравнивает обороты «как есть»/«зеркально» — для сложных случаев
   (частичные оплаты, авансы, взаимозачёты) может понадобиться
   сопоставление по накопительному сальдо, а не только по отдельным
   документам.
